# Public documentation

Keep README.md and release descriptions focused on features, controls, installation, compatibility and concrete known limitations.
Do not add automated-test counts or boilerplate such as "Changes pass automated boundary tests but still need a live game test" or "still needs in-game verification" to those public descriptions.
Keep validation methods and results in BUILD.md, tests/ and validation/ instead. Do not replace removed boilerplate with unsupported claims that a feature works.
